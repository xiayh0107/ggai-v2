# Canvas 前端退化复盘

一次并行重写曾丢失或改变若干已有交互。本文档记录已修复的退化清单、根因模式与防复发规则。**改动 canvas 交互前先读本文，并逐条过一遍文末清单。**

当前交互基准只有 `DESIGN.md`、本清单与 `app/src/components/canvas/` 的现行实现；仓库不保留并行旧实现作为参考。

## 退化清单（均已修复）

### 1. 拖线建节点交互丢失

- **现象**：按住端口无法拖出跟随光标的虚线；「拖到实体松手完成连接、拖到空白松手弹类型菜单、菜单打开期间虚线保持、选好类型后新节点落在线头、虚线无缝变成真实连线」的完整链路断了。
- **修复**：恢复旧版拖线链路；原位轻点端口仍在端口旁直接开菜单，两种习惯并存。节点、任务、集合、多选组的端口全部支持拖拽。
- **回归测试**：拖线到空白建节点（含落点坐标断言）、拖线到实体完成连接。

### 2. 文本节点工具条被指令 chips 占用

- **现象**：选中文本节点，浮动工具条显示「改写 / 缩短」等指令，旧版的粗体 / 斜体 / 标题 1 / 标题 2 不见了。
- **根因**：把本应留在输入区的指令搬上了工具条，违背旧版分工——**格式标记在工具条，指令在输入区**。
- **修复**：`marksFor` / `toggleMark`（`app/src/plugins/builtins/index.tsx`），样式存节点 payload，带按下态高亮、标题互斥、可撤销。
- **回归测试**：标记切换与互斥。

### 3. 格式标记不生效（斜体点了没反应）

- **现象**：工具条切斜体，正文毫无变化。
- **根因**：样式写进了 `node.payload`，但内联产物视图拿不到 `node`（`NodeArtifactViewProps` 没有该 prop），渲染时无处读取——**数据管道在组件边界断掉**。
- **修复**：`ArtifactView` 增加可选 `node` prop；内联视图与右侧查看面板的正文都套用 payload 样式。
- **教训**：payload 驱动的样式必须在每一个渲染点套用，新增渲染形态时同步检查。

### 4. 产物查看变成居中弹窗 / 只能跳新标签页

- **现象**：「打开产物」离开画布或弹居中浮层。
- **根因**：并行重写未沿用已有右侧抽屉形态。
- **修复**：统一抽屉壳 `CanvasRightDrawer`（右侧贴边、浅色背板、Esc / 背板点击关闭），产物查看与详细日志共用；Stage 里合并为单一 `sidePanel` 状态，打开一个替换另一个。
- **回归测试**：抽屉形态断言、文本 / 图片 / 文件三种产物形态。

### 5. 详细日志入口缺失、结构化渲染丢失

- **现象**：节点上只有「活动记录」，没有详细日志入口；入口补回后第一版是纯文本罗列，丢了旧版的结构化前端渲染。
- **修复**：活动记录条加「详细日志」入口；daemon 持久日志游标分页读取（刷新后仍可回看，未结束每 2.5s 轮询）；日志页签结构化渲染——`→` 工具调用与 `←` 结果合并为工具卡片、thinking / text / warning / meta 分类图标配色、超 180 字折叠；另有「过程」页签（友好步骤）与复制日志。
- **回归测试**：工具卡片合并（不裸显 `→ write_file`、结果计数）、分页、复制 / 刷新 / 页签切换。
- **教训**：“有入口”不等于“恢复”——旧版的渲染质量（合并、分类、折叠）也是行为的一部分。

### 6. 右侧面板内滚轮仍然缩放画布

- **现象**：光标在抽屉里滚动，画布跟着缩放。
- **根因**：画布缩放是 stage 元素上的**原生** wheel 监听（`passive: false`），React 合成事件的 `stopPropagation` 拦不住它——原生监听在冒泡链上先于 React 根委托触发。
- **修复**：抽屉容器声明 `data-canvas-side-panel`，stage 的 wheel 处理器对该子树直接放行（不 `preventDefault`，面板保留原生滚动）。
- **回归测试**：侧栏子树内 wheel 不改变 camera、面板外滚轮仍正常缩放。
- **教训**：stage 上的原生事件监听（wheel / pointer）对任何新浮层都要显式判定事件归属。

### 7. 缩小画布隐藏产物预览与「打开产物」

- **现象**：zoom < 0.72 时未选中任务降级为 compact，节点内容变成「图标 + N 个产物」占位；zoom < 0.42 时整张折叠。
- **根因**：重写时擅自新增缩放降级（LOD）——**未被要求的“改进”本身就是退化**。
- **修复**：`deriveTaskPresentation` 移除 zoom 维度，只保留显式收起。
- **回归测试**：presentation 断言更新（恒为 expanded，除非显式 collapsed）。

### 8. 右侧面板缺少节点工具条

- **现象**：打开产物后，右侧面板没有节点那条浮动工具条；且不能依赖节点处于选中态。
- **修复**：viewer 请求携带 `nodeId`；面板工具条完整镜像节点浮动工具条（提示词控件 / 格式标记或指令 chips / 复制 / 删除），与节点选择工具条走同一命令通道，与选中态解耦。
- **回归测试**：四个按钮的渲染与回调、指令 chips 回调。

### 9. 从来源节点新建空节点后，Agent 上下文丢失

- **现象**：从图片端口新建空文本节点，输入“评价这幅图”后，界面显示图片来源标签，但 Run 的 `directInputs` 与 verified artifact attachment 都为空。
- **根因**：空文本节点被采用为 Task 输出槽时，`CreateTaskForOutputSlot` 只设置 `homeTaskId`；原来的 `图片 → 文本节点 source/full` 没有提升为 `图片 → Task`。UI 来源 selector 能看到 Node 入边，而 context compiler 只读取 Task 入边，形成两套事实源。
- **修复**：抽取共享 context-bearing edge selector；输出槽创建在共享 reducer 中原子提升有效来源，相同来源去重且 `full` 优先，`none` 永不提升。实现不按插件 ID 分支。
- **回归测试**：覆盖 `gesture plan → command reducer → Task context compiler → artifactRefs`，并使用社区命名空间插件 ID 证明插件无关。

### 10. 输出槽晋升后同一来源画出两条连线

- **现象**：空槽节点被采用为 Task 输出槽后，画布上同一来源同时出现 `来源 → 任务` 与 `来源 → 节点` 两条线。
- **根因**：#9 的晋升是**复制**——新建了指向任务的连线，但原指向槽节点的上下文连线没有移除。
- **修复**：晋升改为**移动**：`CreateTaskForOutputSlot` 在新建任务入边后，同一原子命令内移除指向槽节点的全部内容连线（`contextRole` 为 `none` 的纯视觉 lineage 不晋升、保留原样）。
- **回归测试**：命令层断言晋升后连线总数不变、内容连线不再指向槽节点、`none` 连线保留。

### 11. 选中生成中的输出节点后，任务详情消失并出现第二个提示词控件

- **现象**：Run 仍在排队 / 生成 / 等待授权，轻点「等待内容」节点后，父 Task 的运行面板
  消失，节点派生 composer 和结构操作重新出现；界面同时表达「正在运行」和「可再次派生」。
- **根因**：Stage 把视觉 selection 当成唯一控制 owner。RunPanel 与 ContextComposer 只判断
  `selection` 是否恰好为单个 Task，没有沿 `homeTaskId` 解析 active / empty owned Node 的
  父任务；复合选择还能绕过单节点修复。
- **修复**：视觉选中与控制权解耦。active Task 或仍为空的 owned slot 始终由父 Task 控权：
  Node 保留选择描边，父 RunPanel 持续显示，节点操作条 / composer / 选择工具条 / 连接端口
  隐藏；复合选择包含此类节点时同样 fail closed。终态且有真实内容后才释放给节点。
- **回归测试**：queued / running / awaiting-permission 的有内容节点；missing / error /
  cancelled / done 的空槽；终态有内容恢复；active owned Node + 第二节点的复合选择；
  ArtifactViewer active-owned 只读。

### 12. 节点活动记录像外接面板，并覆盖提示词控件

- **现象**：「活动记录」在 Node 下方绝对展开为长列表，超出节点边界、与节点视觉脱节；
  z-index 又与 ContextComposer 竞争，列表和提示词控件互相覆盖。
- **根因**：把过程详情塞进 Node chrome，并用 `top-full + absolute` 绕过节点 frame；状态摘要、
  友好过程和原始日志同时占据画布层，没有统一面板 owner。
- **修复**：Node 只保留固定一行状态摘要与「查看过程 / 详细日志」入口；两种详情进入同一个
  右侧抽屉的不同页签。owned 空槽也使用当前 Task runId 显示精确状态；失败 / 取消保留
  精确状态，成功终止或缺少可用状态但仍无内容时显示「未生成内容」，不误报绿色完成。
  抽屉圈定焦点、恢复触发焦点并隔离背板 pointer。
- **回归测试**：活动条无 inline steps、过程 / 日志初始页签、owned-empty 生命周期、抽屉
  Tab 圈定 / 焦点恢复 / 背板不穿透，以及 Stage 中详情抽屉与 composer 的切换。

### 13. 连线指向隐藏的单产物 Task 标题条

- **现象**：单产物 / 生成阶段的 Task 标题条被隐藏后，外部连线仍以 Task 的交互框为终点，
  线头悬在节点上方，甚至先向上绕行再折回节点。
- **根因**：边层把 Task 的逻辑实体直接交给 `taskInteractionBounds`，没有考虑该 Task
  当前没有可见标题条；逻辑端点与视觉端点脱节。
- **修复**：对 chromeless Task 的外部边，将 Task 视觉映射到其首个可见输出 Node；Task 与
  自身输出槽的内部边仍然隐藏，避免重复线头。
- **回归测试**：外部 Node → chromeless Task 的路径终点必须落在输出 Node 可见边界。

### 14. Run 刚启动时重新出现「生成中 / 尚无产物」Task 残壳

- **现象**：从已有内容派生或在画布空白提交目标后，Run 已进入 queued / running，但 Agent
  还没有发出首个 output/path 事件；画布短暂显示完整 Task 卡、状态徽章和「尚无产物」。
- **根因**：运行时 `ghosts` 初始为空，selector 把 `0 Node + 0 ghost` 无条件归为 `task-card`，
  把“尚未发现产物类型”误当成“未运行 draft”。
- **修复**：active 的零输出 Task 立即投射非持久化节点外壳；真实 ghost / Node 到达后原位
  替换。临时节点不猜插件类型，但保留通用节点头部、白色生成面、活动状态与同一运行控件；
  外部连线落在可见节点边界。
- **回归测试**：queued / running + empty ghosts 均为 `title-strip` 容器且有 provisional ghost；
  draft 仍是 task-card；Stage 不含「尚无产物」或 Task 菜单；临时节点有 header、activity 与
  run control，边界计算返回 ghost frame。

### 15. 提交提示词后，输入控件突然缩成另一条运行胶囊

- **现象**：提交前是完整提示词控件，Run active 后整块控件被卸载，换成宽度、位置和高度都
  不同的「正在运行 / 日志 / 取消」小条；用户会误以为上下文输入消失或界面重新布局。
- **根因**：把 prompt composer 与 run status 当作两个互斥组件，而不是同一交互控件的生命周期。
- **修复**：提示词外壳和输入表面跨状态保持；active 时只把输入内容原位换成生成动画与目标，
  发送键原位换成取消，日志入口留在原底栏。锚点和屏幕宽度随节点与相机缩放稳定。
- **回归测试**：draft → queued / running → done / cancelled 的共享 surface 几何保持一致；
  运行控件内部切换不替换 surface DOM，不得新增第二张运行卡，终态后 textarea 原位恢复。

## 根因模式

1. **复制架构代替滚动演进**：按记忆并行重做交互，没有逐条对照当前行为基准。
2. **数据管道断点**：payload、nodeId 这类数据在 props / 请求边界丢失，下游静默拿不到。
3. **事件系统差异**：原生监听与 React 合成事件并存时，浮层被穿透。
4. **擅自“改进”**：缩放降级、居中弹窗等未要求的形态变化，对用户就是功能丢失。
5. **只恢复入口，不恢复质量**：日志有了面板但丢了结构化渲染。
6. **修复只覆盖终态**：标题条减重只处理了「有真实产物节点」的状态，生成阶段（只有 ghost 占位卡）漏判，完整标题条在生成时重新顶出来——行为修复要覆盖实体的全生命周期（生成中 / 完成 / 失败 / 选中 / 未选中），不只终态。
7. **视觉选中与控制所有权混用**：selection 可以变，但 active Run、权限与重试仍属于父 Task；
   控制面必须从领域归属派生，不能从蓝框对象猜测。
8. **子视图冒充上位产品**：为了解决一个局部生命周期（如删除节点后仍可查看生成文件），
   直接把新的 artifact catalog 命名为整个「资源库」，会隐去项目文件、节点能力、连接与运行环境等
   已稳定的信息架构。实现 provider 前必须先确认它在上位 IA 中的位置，详见
   [`RESOURCE-LIBRARY.md`](./RESOURCE-LIBRARY.md)。

## 防复发清单（改 canvas 前过一遍）

- [ ] 对照 `DESIGN.md` 与当前实现列出本次涉及交互的等价行为，逐条确认不丢失。
- [ ] 行为修复覆盖实体全生命周期：生成中（ghost 占位）/ 完成 / 失败 / 选中 / 未选中都看一眼，不只验证终态。
- [ ] 新增浮层 / 面板：声明 `data-no-drag`（指针）与 `data-canvas-side-panel`（滚轮），检查 stage 原生监听是否穿透。
- [ ] Modal 抽屉：检查 Tab 圈定、Esc / 背板关闭、焦点恢复，以及背板 pointer 不穿透画布。
- [ ] Task-owned Node：active 与 owned-empty 下检查单选、复合选择、产物抽屉都不能旁路父 Task 控制权。
- [ ] payload 驱动的样式 / 行为：在所有渲染点套用（内联视图、右侧查看面板、任何新形态）。
- [ ] 跨组件数据（nodeId、payload 等）在请求 / props 边界显式传递，不留静默 undefined。
- [ ] 不引入未要求的内容隐藏、降级或形态变更；确需引入时先取得明确确认。
- [ ] 恢复旧功能时连同其呈现质量一起恢复（合并、分类、折叠、态样）。
- [ ] 回归测试覆盖交互行为本身（落点坐标、事件目标归属、命令派发、态样断言），不只是渲染快照。
- [ ] UI 显示“来源”时，用跨层测试确认同一来源最终进入 `pack.json.inputs`；`full` artifact 同时进入 daemon verified attachment 解析链路。
- [ ] 新增资源列表 / catalog 时，先对照 `RESOURCE-LIBRARY.md` 确认它是哪个 provider；不用子视图取代资源库全局壳。
- [ ] Workspace 一级「资源库」入口在零项目时仍可进入，且不自动选择最近或第一个项目；Canvas 深链才可带显式项目 scope。
- [ ] 未接入的资源 provider 保留诚实规划态，不隐去稳定 IA，不用样例数据或死操作伪装可用。
- [ ] 收尾跑全量验证：`npm run lint` + `npm test` + `npm run build`（PR 前 `npm run verify`）。
